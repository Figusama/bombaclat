# Видеоаудит кассовой дисциплины — Datathon ForteBank

Локальный AI-сервис: по видеозаписи кассы выдаёт вердикт `violation` / `no_violation`, список возможных
нарушений с типом, таймкодом, кадрами-доказательствами и ссылкой на нормативный акт НБРК. UI + API с ключом.
Все модели работают локально (Apple Silicon через MLX или CUDA через transformers), облачные сервисы не используются.

## Для жюри
- Публичный URL сервиса (UI и API): **см. файл `docs/SUBMISSION.md`** (адрес туннеля и API-ключ).
- API: `POST /api/v1/analyze` (multipart `file`, .mov) → `job_id`; `GET /api/v1/jobs/{job_id}` → статус и результат по схеме ТЗ. Заголовок `X-API-Key` обязателен. Подробнее — `docs/api.md`.
- Обработка одного видео: 10–50 с (видео 142 с — до ~160 с), один воркер, запросы обрабатываются последовательно.

## Быстрый старт

```bash
python3.13 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # задать API_KEY
# веса (один раз, ~6 ГБ; дальше работает офлайн):
.venv/bin/hf download mlx-community/Qwen3.5-9B-4bit
.venv/bin/hf download PekingU/rtdetr_r50vd
./run.sh                        # http://localhost:8000  (UI) ; ./run.sh --tunnel — плюс публичный URL cloudflared
```

Проверка через API (см. `docs/api.md`):
```bash
curl -X POST http://localhost:8000/api/v1/analyze -H "X-API-Key: $API_KEY" -F "file=@X-22.mov"
curl http://localhost:8000/api/v1/jobs/<job_id> -H "X-API-Key: $API_KEY"
```

## Архитектура

```
видео .mov ─► кадры 2 fps (PyAV)
            ├► RT-DETR (люди) ─► шкала «сколько людей в кассе» ─► события вход/выход, границы сегментов
            ├► VLM grounding первого кадра ─► ROI: стол, сейф, ноутбук, дверь, машинка (без привязки к ракурсу)
            ├► VLM по сегментам (4 кадра + кропы сейфа/ноутбука/стола) ─► JSON наблюдаемых ФАКТОВ
            └► движок правил (pipeline/rules.py) ─► нарушения: тип, таймкод, кадры, факты
                                                   └► каталог (catalog/violations.yaml) ─► НПА: документ, пункт, цитата
```

Ключевой принцип — **VLM не ставит диагноз**. Модель отвечает только на вопросы о том, что видно
(сколько людей, открыт ли сейф, есть ли деньги на столе, что делает кассир, показан ли документ…).
Нарушение выводится детерминированными правилами над временной шкалой фактов, поэтому:
- каждое нарушение объясняется конкретными фактами и кадрами, без выдуманных юридических выводов;
- правила не зависят от угла съёмки: зоны (стол, сейф, дверь) находит сама модель на каждом видео;
- один и тот же набор фактов покрывает 25 типов, включая те, которых нет в обучающем датасете.

### Модели (все — open source с коммерческой лицензией)
| Назначение | Модель | Лицензия |
|---|---|---|
| Факты и grounding | `mlx-community/Qwen3.5-9B-4bit` (Qwen3.5-9B, 4-bit, ~6 ГБ) | Apache-2.0 |
| Детекция людей | `PekingU/rtdetr_r50vd` (RT-DETR) | Apache-2.0 |

Модель заменяется параметром `MODEL_ID` в `.env`; бэкенд `VLM_BACKEND=mlx` (Apple Silicon) или `hf`
(transformers, CUDA). Выбор модели сделан по мини-бенчмарку на размеченных кадрах датасета (`tools/bench_vlm.py`,
результаты в `reports/bench_*.json`).

## Типы нарушений
Полный каталог с нормативными ссылками — `catalog/violations.yaml` (25 типов). Для каждого типа указаны:
что считается нарушением, как выглядит норма, приоритет, документ/пункт/цитата и степень основания
(`confirmed` — пункт прямо описывает требование; `indirect` — применим по смыслу; `proposed` — нужна сверка
с внутренними документами банка).

Нормативная база: Постановление Правления НБРК от 29.11.2019 № 231 (кассовые операции и инкассация),
Постановление Правления НБРК от 24.02.2020 № 14 (охрана и устройство помещений). Тексты — `research/npa/`.

## Оценка
`python tools/run_eval.py --tag <имя>` прогоняет размеченные видео и пишет `reports/eval_<имя>.md`:
точность вердикта, recall/specificity, попадание таймкода в ±2/±4 с, точность типа, латентность, срез по ракурсам.

Результат на обучающем датасете (40 уникальных видео, 21 с нарушением / 19 без; прогон `r6`, M4 Pro):

| Срез | n | Вердикт | Полнота | Специфичность | Таймкод ±4 с | Тип верный | Латентность p50 / max |
|---|---|---|---|---|---|---|---|
| Все | 40 | 88% | 81% | 95% | 70% | 70% | 19 с / 70 с |
| Ракурс A | 26 | 85% | 77% | 92% | 69% | 62% | 20 с / 70 с |
| Ракурс B | 10 | 90% | 80% | 100% | 50% | 100% | 14 с / 42 с |
| Ракурс C | 4 | 100% | 100% | 100% | 100% | 67% | 25 с / 25 с |

Ложных срабатываний: 1 из 19 нормальных видео. Пропуски: ключ в замке сейфа (не виден на 464×848),
«нет документа клиента» (правило намеренно консервативное), два спорных случая ручного пересчёта.
Полные логи — `reports/eval_r6.md`.

## Ограничения и известные ошибки
- Ключ, оставленный в замке сейфа, на видео 464×848 занимает несколько пикселей: VLM его не различает даже на
  4x-кропе (проверено на Х-22/Х-23), поэтому тип `safe_key_left` имеет низкую полноту. Содержимое экрана
  ноутбука и дверца сейфа по кропам распознаются надёжно (на размеченных кадрах — без ошибок).
- Правила проверяют только визуально наблюдаемое; корректность проводок, сумм, подлинность документов
  не проверяются и в вердикт не входят.
- Люди за стеклянной стеной отфильтровываются по положению относительно двери/стола; при ракурсе, где дверь
  не видна, фильтр менее надёжен.
- Результат — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.
